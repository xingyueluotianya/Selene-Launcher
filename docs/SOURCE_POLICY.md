# 下载源与内容 Provider 政策

## 原则

Selene 将“受信元数据”“内容地址”“用户配置”分开。任何第三方源必须具有明确的服务地址、API 文档、许可与限流规则。

## 计划内 Provider

| 类型 | 目标 | 说明 |
|---|---|---|
| 游戏元数据 | Mojang 官方 `version_manifest_v2.json` | Java Edition 的权威版本目录；已接入并缓存 |
| Java 运行时 | Mojang Runtime，可信 OpenJDK 作为后备 | 按平台、架构、Java 主版本选择 |
| 社区内容 | Modrinth | 使用公开 API 并缓存元数据 |
| 社区内容 | CurseForge | 遵守 API Key 与内容分发限制 |
| Loader 镜像 | BMCLAPI | 作为 Fabric/Forge/NeoForge 官方源失败时的候选源；仍执行官方 SHA-1/大小校验 |
| 知识入口 | MC 百科 | 默认打开项目页，不抓取受限内容 |
| 自定义源 | 用户配置 | 必须显式信任，独立标识，不伪装官方源 |

## `mor` 与 `cus`

这两个名称目前不能唯一对应到可安全实现的网站或 API。后续接入前需要记录：

- 完整网站与 API 地址
- 服务条款及客户端分发许可
- 鉴权方式和限流策略
- 项目标识、版本依赖、文件哈希的数据结构
- API 不可用时的降级行为

在这些信息明确前，不写猜测性适配器，也不抓取网页替代正式 API。

## 失败与安全策略

- 候选地址按用户策略排序，失败后指数退避并换源。
- 文件必须经期望大小和哈希校验后进入实例。
- Provider 返回的文件名不可直接作为本地路径。
- UI 必须显示文件来自哪个 Provider，允许用户禁用来源。
- 遥测默认关闭，诊断上传需逐次确认并脱敏。
